# Dark Protein Evidence Atlas

**面向人类功能证据有限蛋白的多层证据浏览与候选审阅平台。**

本项目围绕一个科学问题展开：**哪些研究不足的蛋白可能具有相近的分子能力，或与已知蛋白共同完成某项生物学任务？**

平台将序列与结构亲缘、实验互作、蛋白家族、核定位、组织表达和文献线索放在同一处浏览，帮助研究人员比较候选、追溯证据并提出可检验的机制假说。当前网站展示的是已有分析结果的冻结快照，不在浏览器中训练模型、计算新的 embedding 或预测新的互作。

> **基础证据快照：2026-10-20；new497排名、核定位与IF/AF展示更新：2026-10-21。**
> 本项目中的“候选”“优先分”和“机制假说”均不等于已经验证的新功能或成功概率。

## 项目目标与分析思路

项目保留两条相互补充、但含义不同的证据路线：

| 路线 | 主要信息与方法 | 回答的问题 |
|---|---|---|
| **分子亲缘路线** | MMseqs2 序列比对、Foldseek 结构比对、Pfam 结构域架构，以及已有 ESM 表示上下文 | 候选与哪些蛋白共享局部序列、折叠或分子能力？有哪些相似点与差异？ |
| **实验协作路线** | 可追溯的实验 PPI、实验类型、原始文献、细胞背景及网络邻域 | 候选与哪些蛋白存在已报告的实验关联？这些关联可能支持什么协作关系？ |

两条路线在**候选层面进行证据整合与解释**，不要求所有数据压缩为一个统一向量，也不要求每个候选同时获得全部模态支持。

我们寻找的“功能团队”可以由不同复合物、瞬时互作或调控环节共同组成。因此，**相互连接不等于属于同一复合物，跨模块互作也不必被视为错误**。GO、Reactome 等知识标签主要作为独立评价或后验解释背景；perturbation 不进入当前发现流程，跨物种进化与 MSA 留待候选精炼。

## 当前网页包含什么

网页围绕原始 **716 名候选基因**组织内容，实验互作来自固定 **9,903 基因**范围的蛋白关联网络。

| 内容 | 数量与范围 |
|---|---:|
| 原始候选 | 716 名，全部保留 |
| 最新人工筛选表保留的候选 | 497 名，标记为 `new` |
| 未保留在最新表中的原候选 | 219 名，标记为 `rejected` |
| 与候选相连的实验关联 | 12,049 条去重无向关联 |
| 按候选方向展开的互作记录 | 12,171 条 |
| 当前网络未观察到互作的候选 | 129 名，继续保留 |
| 合格的已知功能参考配对 | 5,111 对，覆盖 354 名候选 |
| 未观察到合格已知参考的候选 | 362 名，继续保留 |
| 最新策展中的家族／结构分组说明 | 81 组 |

这些数量有不同的统计单位：一条候选之间的无向互作可以对应两条候选方向记录；5,111 条分子配对也不代表 5,111 名候选。

### 如何理解 new 与 rejected

- **`new`**：该蛋白在用户最新的 497 名筛选表中，包含该表新增的家族与成员注释。它不表示“新发现的蛋白”或“已经证明的新功能”。
- **`rejected`**：该蛋白属于原 716 名单，但没有保留在最新人工筛选表中。它不表示生物学阴性、实验失败或没有研究价值。
- 原始记录和证据继续保留，可以查询、比较和导出。未提供的逐基因移除原因不会被补造。

## 主要功能

- **候选总表**：在原表直接查看new497新排名、计分分量与定位；按基因、别名、UniProt accession、伙伴和功能关键词搜索。
- **多条件筛选**：按名单状态、定位证据层级、家族、证据路线、蛋白长度和实验室条件名单重叠筛选。
- **家族与成员比较**：可切换家族排序使同族相邻，分别展示家族背景、各成员已有功能及差异。
- **完整实验互作**：查看全部已记录伙伴、实验类别、来源 PMID、实验背景、伙伴功能和原始记录；可浏览可点击的互作邻域图。
- **完整分子亲缘表**：分别查看序列与结构比对、覆盖范围、相似区间、结构可信度和共享／额外结构域。
- **蛋白详情**：在原“证据概览”查看新分数与来源，在原“结构 / IF / 定位 / 表达”查看HPA原图、主／附加定位、原tier与AlphaFold三维结构；整合既有结构域、表达、文献及机制解释。原独立排名／定位地址自动跳转到此页面。
- **并排审阅**：选择 2–4 名候选进行证据比较。
- **导出与个人笔记**：导出当前筛选的完整结果、单蛋白档案或个人关注与笔记；导出不受当前分页限制。

**关注和笔记只保存在当前浏览器的本地存储中，不会写回仓库或科学源数据。** 更换设备、浏览器或清除存储后可能丢失，请主动导出备份。

## 证据与结果的解释边界

### 互作不等于直接结合

AP-MS、co-IP、二元报告和近邻标记具有不同的实验含义。捕获关联可能通过桥接蛋白或共复合物产生；二元报告也不能替代纯化条件下的直接结合或界面验证。跨数据库重复收录和多个 PMID，不能直接当作独立实验复现次数。

网页中的互作范围是**固定网络内与 716 名候选相连的已记录蛋白关联**，不是全人类互作关系的穷尽。

### 亲缘关系不等于完整功能转移

局部序列或折叠相似可以提示共享分子能力，但不能自动证明相同底物、定位、通路或互作伙伴。相同结构域的类别也不一定是同一近缘蛋白家族。

不同 HGNC 基因节点继续独立保留；例如 FAM156A/B 的共享序列依赖会明确标注，不能把无法区分的分子特征当成两份独立证据。

### 缺失不等于阴性或新颖性

没有明确 FUNCTION 注释、不在当前网络中、缺少合格参考，均不表示无功能或“从未研究”。定位层级是来源支持强度的分层，不是定位概率；较低层级也不等于非核定位。

### 伙伴过程概览不是富集分析

伙伴功能类别来自已有注释的关键词汇总，可包含多标签。该汇总没有背景集合比较、P 值或 FDR，不能作为候选已经参与某通路的统计证明。

### 论文数和优先分如何理解

- **关联文献数**：人类 NCBI Gene 的 Gene–PubMed 链接中唯一 PMID 的数量，不是被引用次数、标题摘要搜索命中数，也不是专门研究该蛋白功能的论文篇数。
- **当前new497优先分**：核定位25、染色质／表观遗传关联35、关联可靠性20、机制机会15、实验便利性5；默认按审查队列与分数排序。未评估项按该项权重50%暂计，并展示上下界；不是0分或已知中等证据。可在原表调整权重，历史716分数仍保留。分数未经实验阳性率校准，不称预测准确率或阳性发现率。
- **实验室名单重叠**：表示条件／构建体名单中的匹配，不等同于互作或功能验证阳性。

## 数据来源与追溯

主要来源包括：

- 身份与蛋白注释：[HGNC](https://www.genenames.org/)、[UniProt](https://www.uniprot.org/)。
- 结构与结构域：[AlphaFold DB](https://alphafold.ebi.ac.uk/)、[Pfam / InterPro](https://www.ebi.ac.uk/interpro/)。
- 实验互作：[BioGRID](https://thebiogrid.org/)、[IntAct](https://www.ebi.ac.uk/intact/)、HuRI、BioPlex 等项目，具体以每条关联的原始来源为准。
- 定位与表达：[Human Protein Atlas](https://www.proteinatlas.org/)。
- 文献索引：[NCBI Gene](https://www.ncbi.nlm.nih.gov/gene/)、[PubMed](https://pubmed.ncbi.nlm.nih.gov/)。

网页保留数据版本、精确基因身份、来源记录和缺失标记。具体 PMID、条目链接与方法门槛可在蛋白详情和“方法与数据来源”页面核查。版本与输入校验信息随网页文件保存于 `docs/downloads/provenance.json`。

## 本地使用与网页发布

完整网页文件上传后，目录结构如下：

```text
.
├── README.md
├── LICENSE
└── docs/
    ├── index.html
    ├── app.js
    ├── model.js
    ├── priority-integrated.js # 原表内的新排名组件
    ├── priority-data/   # new497分量与逐边依据
    ├── review-data/     # 核定位、HPA IF和AF元数据
    ├── review-media.js
    ├── review.css
    ├── style.css
    ├── icon.svg
    ├── .nojekyll
    ├── data/          # 候选、互作、亲缘与注释快照
    └── downloads/     # 原始注释表、配对表及版本记录
```

本地预览不需要安装前端依赖。在仓库目录运行：

```sh
python3 -m http.server 8766 --bind 127.0.0.1 --directory docs
```

随后访问 <http://127.0.0.1:8766/>。请完整保留 `data/`、`priority-data/`、`review-data/`、`vendor/` 与 `downloads/`，不要只复制 `index.html`。

GitHub Pages 可选择 **Settings → Pages → Deploy from a branch → main → /docs → Save**。部署完成后的预期地址为：

**https://reecardoo321.github.io/Dark-protein-evidence-atlas/**

该地址需要在网页文件上传、Pages 配置和部署成功后才会生效。发布配置可参考 [GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。
